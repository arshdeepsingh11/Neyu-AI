# NEYU Health — Go-live runbook (Phase 9)

**For:** DevOps · **Owner:** Arsh · **Site:** https://neyuhealth.com · **Repo:** `github.com/arshdeepsingh11/Neyu-AI` (public), branch **`japanese-style`**

The live site today runs the old version on **SQLite**. This runbook moves it to the new version on **PostgreSQL 16 + Redis** and keeps every patient account and file.

| | |
|---|---|
| Downtime | about 10–15 minutes (Part C only) |
| Rollback | under 5 minutes; the old version and old database stay untouched (Part F) |
| Tested | Rehearsed on Ubuntu 24.04 with a database shaped like the live one: practice + real import, report-file move, seed, build, PM2 cluster, zero-downtime reload, nginx + TLS, backup + restore, rollback, `check.sh` |
| Your time | Part A 15 min · Part B 60 min (site stays up) · Part C 15 min · Part D 15 min · Part E 20 min |

Run every command as the **same Linux user that runs PM2 today** (not root). Use `sudo` only where it is written.
Don't run app scripts with `sudo`: the files they create would belong to root and the app couldn't read them.

---

## What changes

| | Old (live now) | New |
|---|---|---|
| Database | SQLite file | PostgreSQL 16 (localhost only) |
| Cache / jobs | none | Redis (localhost only) + background worker inside the app |
| App processes | 1 (PM2 fork) | 1 per CPU core (PM2 cluster), zero-downtime reloads |
| Patient report files | inside the database | `/var/lib/neyu/storage`, encrypted (AES-256-GCM) |
| Daily jobs | cron → `/api/cron/daily` | built-in worker (no cron needed, except backup) |
| Node.js | 20 | **22** |

## Server requirements

- Ubuntu **24.04** (or 22.04, see B2). 2 vCPU, 4 GB RAM (+2 GB swap), 40 GB SSD.
- Inbound: **22, 80, 443** only. PostgreSQL (5432), Redis (6379) and the app (3000) stay on localhost.
- Outbound HTTPS (443) to: `registry.npmjs.org`, `binaries.prisma.sh` (database engine, downloaded during `npm ci`), `github.com`, `fonts.googleapis.com` + `fonts.gstatic.com` (build), `generativelanguage.googleapis.com` (AI), and **SMTP** to `smtp.resend.com:465`.
  Later, for app notifications: `fcm.googleapis.com`, `oauth2.googleapis.com`, `api.push.apple.com`.

## Part A — Email domain (any day before go-live)

Patients get their sign-up code by email through **Resend**. Resend only sends to everyone once **neyuhealth.com** is verified.

1. Resend → **Domains** → **neyuhealth.com**.
2. Click **Auto configure** → sign in to GoDaddy → approve. Resend adds the DNS records itself.
   *(Manual way: GoDaddy → neyuhealth.com → DNS → add every record shown in Resend exactly: TXT `resend._domainkey`, CNAME `rsend`, CNAME `send`, and any others listed. If a record with the same name already exists, edit it instead of adding a second one.)*
3. Recommended: TXT `_dmarc` = `v=DMARC1; p=none;` (fewer emails in spam).
4. Click **Verify DNS Records** → wait for **Verified** (minutes, sometimes a few hours).
5. Resend → **API keys** → **Create** → permission **Sending access** → domain neyuhealth.com. Keep it for B5 (`SMTP_PASS`).
6. Ignore **anrahealth.com** in Resend (not used).

## Part B — Prepare (the live site keeps running)

### B1 · Look at the current setup (write the answers down)

```bash
whoami                                   # the PM2 user — use it for everything below
pm2 ls                                   # expect "neyu-health" online
lsb_release -ds; node -v; nproc; free -h; df -h /
cat /var/www/neyu/deploy/ecosystem.config.js | grep cwd      # expect /var/www/neyu/.next/standalone
grep -E '^\s*DATABASE_URL=' /var/www/neyu/.env               # path of the old SQLite file
git -C /var/www/neyu remote -v
ls /etc/nginx/sites-enabled/
sudo certbot certificates                 # which certificate covers neyuhealth.com / www
```

If the old SQLite path is relative (`file:./dev.db`), the file is `/var/www/neyu/prisma/dev.db`.

### B2 · Install software

```bash
sudo apt update
# Node.js 22 (replaces 20; the running site keeps working until it restarts)
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs git nginx sqlite3 redis-server certbot python3-certbot-nginx
sudo npm i -g pm2@latest && pm2 update  # restarts the old site once (a few seconds) on Node 22
pm2 install pm2-logrotate                 # keeps PM2 logs from filling the disk
```

PostgreSQL 16:

```bash
# Ubuntu 24.04:
sudo apt install -y postgresql-16 postgresql-client-16
# Ubuntu 22.04 only — add the official PostgreSQL repository first:
#   sudo apt install -y postgresql-common && sudo /usr/share/postgresql-common/pgdg/apt.postgresql.org.sh
#   sudo apt install -y postgresql-16 postgresql-client-16
```

Redis: Ubuntu's defaults are right (localhost only, `maxmemory-policy noeviction`, which the job queue needs).
`sudo systemctl enable --now redis-server && redis-cli ping` → `PONG`.

Swap (if `free -h` shows none):

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### B3 · Folders

```bash
sudo mkdir -p /var/lib/neyu/storage /var/backups/neyu
sudo chown -R "$USER" /var/lib/neyu /var/backups/neyu
chmod 700 /var/lib/neyu/storage /var/backups/neyu
```

### B4 · New code in a separate folder

```bash
git clone -b japanese-style https://github.com/arshdeepsingh11/Neyu-AI.git /var/www/neyu-new
git -C /var/www/neyu-new log -1 --oneline        # must be the merged commit Arsh tells you
```

PostgreSQL tuning (sized for 4 GB RAM; for 8 GB double the four memory lines in the file):

```bash
sudo cp /var/www/neyu-new/deploy/postgresql-neyu.conf /etc/postgresql/16/main/conf.d/neyu.conf
sudo systemctl restart postgresql
```

### B5 · Settings file

```bash
cd /var/www/neyu-new
APP=/var/www/neyu-new bash deploy/make-env.sh /var/www/neyu/.env
```

This script:
- creates the PostgreSQL user + database `neyu` with a new random password and writes `DATABASE_URL`,
- **carries over** `GEMINI_API_KEY`, wearable keys and `TOKEN_ENC_KEY` from the old `.env`,
- generates new `ADMIN_SESSION_SECRET`, `CRON_SECRET`, `ADMIN_PASSWORD`, `METRICS_TOKEN`,
- lists the lines still **EMPTY**.

Fill the empty lines: `nano /var/www/neyu-new/.env`

| Line | Value |
|---|---|
| `SMTP_PASS` | the Resend key from A5 |
| `SUPER_ADMIN_USERNAME` / `SUPER_ADMIN_PASSWORD` | from Arsh |

> ⚠️ **`TOKEN_ENC_KEY` must never change.** It opens saved wearable sign-ins and every report file.
> The script copies the old value (or the old `ADMIN_SESSION_SECRET` if the old key was empty, which is what the old code used).
> Save the finished `.env` in the company password manager. If the key is lost, the files can't be opened.

## Part C — Go-live (site offline about 10–15 minutes)

Pick a quiet time (late evening). Copy the commands one block at a time, **all in the same terminal window** (C1 sets `$FINAL`, used in C2).

### C1 · Stop the old site and freeze its database

```bash
pm2 stop neyu-health
OLDDB=/var/lib/neyu/neyu.db            # the path from B1
FINAL=/var/backups/neyu/neyu-before-postgres-$(date +%F).db
sqlite3 "$OLDDB" ".backup '$FINAL'" && ls -lh "$FINAL"
```

### C2 · Copy all data into PostgreSQL

```bash
cd /var/www/neyu-new
npm run db:import -- "$FINAL"          # ✓ Import complete · every row count verified (all or nothing)
npm run storage:move                   # report files → /var/lib/neyu/storage (encrypted)
npm run db:seed                        # super admin account + email settings for every patient
```

### C3 · Swap folders and start the new version

```bash
mv /var/www/neyu /var/www/neyu-old-sqlite
mv /var/www/neyu-new /var/www/neyu
pm2 delete neyu-health                  # the old process was single (fork); the new one is a cluster
cd /var/www/neyu && cp .env .next/standalone/.env      # latest settings
pm2 start deploy/ecosystem.config.js && pm2 save
pm2 ls                                  # one "neyu-health" per CPU core, all online
curl -s http://127.0.0.1:3000/api/v1/health      # "status":"ok"
```

### C4 · Nginx

Make sure one certificate covers both names (keeps the existing one when it's still valid):

```bash
sudo certbot certonly --nginx --cert-name neyuhealth.com -d neyuhealth.com -d www.neyuhealth.com \
  --keep-until-expiring --deploy-hook "systemctl reload nginx"
```

If certbot asks to update the certificate's names, answer **U**. Then install the new site file (the old setup is saved for rollback):

```bash
sudo tar -czf /var/backups/neyu/nginx-old.tgz -C /etc/nginx sites-available sites-enabled
ls /etc/nginx/sites-enabled/            # note the old NEYU file name
sudo cp /var/www/neyu/deploy/nginx-neyuhealth.conf /etc/nginx/sites-available/neyuhealth.com
sudo ln -sf /etc/nginx/sites-available/neyuhealth.com /etc/nginx/sites-enabled/neyuhealth.com
# if the old NEYU site had another file name in sites-enabled, remove that link: sudo rm /etc/nginx/sites-enabled/<old name>
sudo nginx -t && sudo systemctl reload nginx
```

### C5 · Check

```bash
bash /var/www/neyu/deploy/check.sh      # must end with "Nothing blocking"
```

The site is live. Go straight on to Part D.

## Part E — Same day, after go-live

1. **Backups** (`crontab -e`, as the PM2 user):
   ```
   15 2 * * * bash /var/www/neyu/deploy/backup.sh >> /var/backups/neyu/backup.log 2>&1
   ```
   Run it once by hand: `bash /var/www/neyu/deploy/backup.sh`. It backs up the database and the report files.
   **Copy `/var/backups/neyu` off this server every day** (another machine or cloud storage). A backup on the same disk is not a backup.
2. **Start after reboot:** `pm2 startup` → run the command it prints → `pm2 save`. Test once with `sudo reboot`.
3. **Monitoring:** an uptime check on `https://neyuhealth.com/api/v1/health` (alert if not 200 or no `"status":"ok"`). Details: `deploy/MONITORING.md`.
4. **Old cron line:** remove the old `/api/cron/daily` curl line from `crontab -e` if there is one (the worker does it now).
5. Save the final `.env` in the company password manager.
6. Keep `/var/www/neyu-old-sqlite` and `neyu-before-postgres-*.db` for **30 days**, then delete them.
7. Monthly restore test: see the top of `deploy/backup.sh`.

## Part F — Rollback (old site back in under 5 minutes)

Accounts or data created **after** go-live are not in the old database. Decide early (same evening).

```bash
pm2 delete neyu-health
mv /var/www/neyu /var/www/neyu-failed
mv /var/www/neyu-old-sqlite /var/www/neyu
cd /var/www/neyu && pm2 start deploy/ecosystem.config.js && pm2 save
sudo rm /etc/nginx/sites-enabled/neyuhealth.com && sudo tar -xzf /var/backups/neyu/nginx-old.tgz -C /etc/nginx
sudo nginx -t && sudo systemctl reload nginx
```

The old SQLite file was only read, never changed. Send `pm2 logs` and the `check.sh` output to Arsh.
To try again later: delete `/var/www/neyu-failed`, drop and recreate the `neyu` database (`sudo -u postgres dropdb neyu`), and start again from B4.

## Problems and fixes

| You see | Fix |
|---|---|
| `npm ci` → can't download from `binaries.prisma.sh` | allow outbound HTTPS to it, run again |
| build stops with "JavaScript heap out of memory" / killed | add swap (B2), run `npm run build` again |
| `P1001 Can't reach database server` | `sudo systemctl status postgresql`; check `DATABASE_URL` |
| `db:import` → "PostgreSQL already has N patients" | the import already ran. To redo: `sudo -u postgres dropdb neyu && sudo -u postgres createdb -O neyu neyu`, then `npx prisma migrate deploy` and import again |
| check.sh → "TOKEN_ENC_KEY can't open existing data" | the key isn't the old one. Copy `TOKEN_ENC_KEY` (or, if that was empty, `ADMIN_SESSION_SECRET`) from `/var/www/neyu-old-sqlite/.env` into `TOKEN_ENC_KEY`, `cp .env .next/standalone/.env`, `pm2 reload neyu-health` |
| no sign-up code email | `npm run email:test -- you@example.com`; it explains the reason (domain not verified, wrong key, port blocked → try `SMTP_PORT=2465`) |
| 502 Bad Gateway | `pm2 ls`, `pm2 logs neyu-health --lines 100` |
| `nginx -t` → no "ssl_certificate" / file not found | run the certbot command in C4 first |
| changed `.env` but nothing happens | `cp .env .next/standalone/.env && pm2 reload neyu-health` |

## Never

- run `npm run db:demo` or anything in `loadtest/` against the live database,
- copy values from a developer's PC `.env`,
- change `TOKEN_ENC_KEY`,
- run app scripts with `sudo`,
- open ports 3000, 5432 or 6379 to the internet.
